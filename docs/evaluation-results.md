### GPT-5.6 Sol token 口径

GPT 全量采用最新 19 份可审计完整样本：`input 3,632,311`（其中 `cached input 3,144,704`）+ `output 66,481` = `3,698,792`。cached input 是 input 的子集，不重复相加；它只在成本核算时从普通 input 中拆出。

旧记录的 `618,944` 只有当时 CLI 的 `tokens used` footer，没有 input、cached input 与 output 分项，不能按当前口径复算。最新样本去掉缓存读取后为 `487,607 uncached input + 66,481 output = 554,088`，与旧 footer 处于同一量级。因此正式总表采用可跨当前 runner 对比的 **3,698,792 总处理 token**，`618,944` 只作为历史 footer，不再作为全量主数字。

## 证据采用口径

- 每个 case 只采用一份完整运行的 runner 输出、diff、status、读取轨迹、judge 与 token，不在题内拼接多轮证据。
- 多份行为等价证据存在时，正式能力表采用最高完整单次完成度；这表示当前组合已展示的能力上限，不等同于稳定通过率。
- 指纹用于复现精确运行，不是整张成绩的自动作废开关。只有改动会影响该 case 实际加载的规则、题面、fixture、模型配置、评分语义或确定性门时，旧证据才失效；未触达普通路径的可选路由资产、维护文档或其他无关改动不阻止合并。
- off 不加载 skill；题面、fixture、评分和模型配置不变时，不因 skill source 变化失效。
- runner token 只在同一模型、宿主和同一统计语义的 on/off 内比较。不同 CLI 的 token 口径不可据此横向推断模型效率；judge token 不计入 runner 对比。
- 原始 transcript、usage、diff、status、manifest、指纹和裁判记录留在本地运行目录与 Git 历史，不进入正式报告。
