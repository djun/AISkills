# 外部能力与协作

需要使用宿主能力、项目规则、附件、专业资料、agent 或多模型协作时读取。它们只是完成任务的手段；现有能力已经足够时，不为“增强”或完整感额外加载。

## 先用已有能力

1. 先遵循宿主、项目规则和用户指定的资源；直接使用宿主已经提供且匹配任务的文档、表格、演示、PDF、浏览器或图像等能力。
2. 从对象、术语、文件、平台和项目现状判断所需领域，不让用户选择内部资料包。只有不同选择会改变目标、验收或高代价路线，且现有证据无法判断时才询问。
3. 外部能力必须直接相关，能够补充当前缺少的知识或工具，并与当前版本和限制兼容；空泛、重复、陈旧或无法验证的内容不加载。
4. 宿主不能实际调用的技能文本只能作为参考资料，不能声称已调用。只在项目根的明确规则、用户点名路径或宿主公开位置查找，不扫描 home、猜测路径或读取秘密。

宿主或项目已有记忆、规格、日志、决策记录和知识库时，在原处读取、更新或提议更新，不复制第二套真相。长期记忆的来源、范围、失效和删除规则见 `references/dao/continuity.md`。

项目根 `.odai/local.md`、宿主提供的 `odai-local` 或用户点名偏好只补充 odai 在当前项目中的做法，不保存任务状态、项目事实、决定或长期记忆。项目规则优先于通用偏好；两者都不得覆盖宿主和当前用户指令，也不得改变 odai 的总纲、必须遵守的门和事实标准。普通方法冲突时，根据当前任务事实选择。读取一次不等于获准写入，也不把一次观察保存成长期规则。

同一任务只保留一份主计划和主状态。宿主、项目或外部能力已经负责计划、拆分、状态和推进时，odai 只补缺少的判断、限制和完成证据，不另建平行计划、规格、账本或阶段。只有原位置不存在、不可用或确实无法记录必要信息时才新建，并明确由谁继续维护。

## 再决定是否下放

默认由当前模型直接完成。只有宿主确实提供相应能力、任务范围和验收已经明确、主流程可以复核结果，而且收益高于启动、交接与冲突成本时，才使用 agent。

适合下放的工作包括：不会发生写入冲突的独立分支、范围明确的大型扫描、对高代价结论的独立质疑，以及输入已经固定的重复执行。上下文高度相关、任务很短、可能写入同一位置或结果无法复核时，不下放。不得虚构模型、价格、能力、并行状态或调用结果；只按宿主实际提供的信息说明成本和能力。

给执行者的最小任务说明只包含：用户目标、必要事实和输入、允许与禁止的范围、必须保持的行为、允许动作、完成标准、停止条件和返回格式。不要复制整段对话或无关技能内容。

下放写入前，确认执行者拿到了同一版本的 `SKILL.md` 和 `references/capabilities/delivery.md`。宿主已完整传递时不重复加载；没有传递就要求执行者在首次写入前读取可访问的原文，摘要不能替代原规则。无法访问或无法确认版本时，只允许只读分析并返回证据。

执行者可在确定范围内自主选择局部做法；新证据如果改变目标、授权、范围、成本或风险，就停止写入并说明。主流程根据原始产物、diff、工具结果或独立证据采纳，不按参与数量或自报完成决定。

并行任务要分开修改对象和依赖，并先验证上游。审查 agent 始终只读；批量修复前先去重并固定已核实的问题清单，修复者只处理该清单，主流程逐项复验后才关闭问题。新发现留到下一轮。

高代价、难撤回或存在多条相近路线的决定，在确定前做一次独立质疑或寻找反证；按证据决定，不按多数票。用户明确要求合议、多模型复核或重型压力测试时，再读 `references/techniques/consensus.md`。

## 改进规则但不擅自改技能

任务中发现会跨任务复发的规则空白、冲突或陈旧做法时，先完成当前任务，再提出有证据的改进候选；不自动修改 skill，也不混入业务待办。用户采纳后，项目规则写入 `.odai/local.md`；要提升到 odai 的唯一源文件须另获维护授权，提升后删除重复的项目规则。候选数量由真实问题决定，不为“持续改进”凑提案。
