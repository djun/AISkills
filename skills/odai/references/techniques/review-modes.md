# 正式与连续审查

仅在用户明确要求正式完整报告、连续 N 轮无阻塞问题、全仓 / 全目录复查、安全审查，或结论将决定合并、发布和安全放行时读取。普通单轮审查不读；范围、严重度与通用规则仍以 `references/capabilities/review.md` 为准。

## 连续审查与修复

开始前明确并保持审查范围、证据基线、相关验证和“本轮无阻塞问题”的判断标准。默认标准是没有阻塞当前目标的问题，且相关验证没有失败；用户明确要求零问题时按用户要求。阻塞问题必须有当前范围可触发的路径和实际影响；证据不足的内容列为待确认或非阻塞观察，维护建议与真实缺陷分开。

每轮都根据当前文件状态和同一范围重新检查。范围内修改、证据基线变化、新增阻塞问题或相关验证失败，会使连续轮次从零重新计算；明确无关的范围外变化不重置。紧凑记录：`第 x/N 轮｜结果｜范围｜关键证据`。不能复用修复前结论、旧任务自报或未完成扫描。

使用 agent 时遵循 `references/dao/leverage.md`：扫描者只读并返回问题与复现证据，主审负责去重、定级和计数。用户已授权修复时，先固定经核实的完整清单，再按 `references/capabilities/delivery.md` 实施；修复后重跑相关验证并重新计算连续轮次，只有主审实际复验后才关闭问题。

## 正式判断输出

- **审查基线**：范围、变更目的、证据基线、主要文件、排除项与重点。
- **问题**：按严重度给出定位、触发条件、影响、最小修复和复查方式；没有问题不凑数。
- **是否通过**：通过 / 修改后通过 / 不通过 / 待确认，并列必须修改、可暂缓和未覆盖项。
- **过程完整性**：说明遗漏、误判、定级争议、工具失败或范围变化；没有就明确未发现。

是否通过按风险和验收影响决定，不按建议数量机械计数：没有阻塞问题，且发布条件和已确认边界成立时可通过；问题明确可修且影响放行时修改后通过；方向错误或存在多处严重缺陷时不通过；证据、范围或责任人未定时待确认。
